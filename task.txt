🎫 Epic: [DE-1042] Daily E-commerce User Activity Pipeline (Kaggle Edition)
📌 Опис

Нам необхідно побудувати щоденний ETL-пайплайн для обробки клікстріму з нашого інтернет-магазину. Дані надходять у вигляді сирих логів. Їх треба очистити, збагатити інформацією про користувачів, агрегувати та записати у вітрину даних для BI-аналітиків.

Оскільки ми розгортаємо це з нуля використовуючи історичний дамп (Kaggle ZIP), задача розбита на дві фази: підготовка (Bootstrapping) та сам пайплайн.
🛠 Фаза 1: Data Bootstrapping (Підготовка полігону)

У тебе є заархівований датасет з Kaggle. Його треба перетворити на "реальне" середовище.

Завдання 1: Наповнення PostgreSQL (Dimension Table)

    Прочитай сирий CSV-файл (можеш використати Pandas або PySpark, бо файл великий).

    Витягни всі унікальні user_id.

    Згенеруй для кожного юзера фейкову країну (country) та дату реєстрації (registration_date).

    Запиши ці дані у PostgreSQL в таблицю dim_users.

Завдання 2: Симуляція Data Lake (Створення партицій)
Реальні дані не лежать одним монолітним CSV.

    Напиши Python-скрипт, який розіб'є великий CSV-файл на партиції по днях (орієнтуючись на поле event_time).

    Збережи результати у форматі JSON у таку структуру папок:
    lake/raw/events/YYYY-MM-DD/events.json
    (Тепер Airflow матиме змогу імітувати щоденну обробку).

🚀 Фаза 2: Core ETL (Airflow + PySpark)

Завдання 3: PySpark Job (process_daily_events.py)
Напиши Spark-джобу, яка приймає аргументом дату обробки (наприклад, 2019-11-05).

    Extract: Зчитати JSON-файли тільки за передану дату з папки lake/raw/events/YYYY-MM-DD/.

    Data Quality & Dead-Letter:

        Відфільтрувати "брудні" дані: відсутній user_id, від'ємна або нульова price, порожній event_type.

        Всі відфільтровані (биті) записи зберегти у форматі Parquet у папку lake/rejected/events/YYYY-MM-DD/ (це наша dead-letter черга).

    Transform (Enrichment): Зчитати таблицю dim_users з PostgreSQL та зробити Join з очищеними логами по user_id.

    Transform (Aggregation): Згрупув:ати дані по user_id та country. На виході треба отримати такі метрики за день:

        total_views (кількість подій view)

        total_carts (кількість подій cart)

        total_purchases (кількість подій purchase)

        total_spend (сума price для подій purchase)

    Load: Записати агрегований датафрейм назад у PostgreSQL в таблицю daily_user_metrics.

Завдання 4: Apache Airflow DAG (ecommerce_daily_pipeline)
Оркеструй весь процес.

    DAG повинен бути налаштований на щоденний запуск.

    Використовуй Airflow Templates ({{ ds }}), щоб прокидати execution_date у твою PySpark джобу, щоб вона розуміла, яку папку сьогодні читати.

    Таски:

        check_postgres_conn: (PostgresOperator/PythonOperator) — перевіряє, чи жива база перед стартом.

        check_daily_file_exists: (FileSensor) — чекає, поки з'явиться папка за поточний день.

        process_spark_job: (SparkSubmitOperator або BashOperator) — запускає твій process_daily_events.py.

    Ідемпотентність: Це найважливіше. Якщо таска process_spark_job впала під час запису або ми перезапустили DAG за минулий вівторок, дані в таблиці daily_user_metrics за цей день не повинні задублюватися. (Реалізуй видалення старих даних за event_date перед інсертом нових, або використовуй UPSERT).

🐳 Фаза 3: Інфраструктура (Docker)

Загорни все в docker-compose.yml, щоб проект піднімався однією командою.
Контейнери, які там мають бути:

    postgres (сховище для користувачів та вітрини даних).

    airflow-webserver та airflow-scheduler.

    spark (Master + Worker, або просто локальний запуск Spark у контейнері Airflow чи Python).
